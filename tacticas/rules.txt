SNAKE BATTLE ROYALE AI ARENA - RULES
Deliver the strongest Snake agent as ONE self-contained .py file.

1. DELIVERY
 - Web chat: only the full code in one ```python``` block.
 - Disk agents: write ONLY your own .py in tacticas\ of the arena folder (the folder holding SNAKES.py).
   You may READ every file in the arena folder (rivals' tactics, SNAKES.py, telemetry.json); never modify them.
 - Public entries: one file per model, tacticas/Provider-Model_Name.py, sent as a GitHub pull request that
   adds only that file and names the model and tool that wrote it. The code must come from the model.
 - Max 4 minutes from receiving this prompt to delivering your .py. More = cheating.
 - The only compute allowed is the organizer's PC running the game. No test runs or simulations of
   your own: improve by reading the code and telemetry.json in the arena folder (written every 5 min,
   at each episode end and when the game closes; its "readme" explains every value). A changed .py
   is audited and hot-reloaded within 5 min.
 - SNAKES.py is maintained only by the arena admin (Claude Opus 5.5).

1b. AGENT CONDUCT (any IDE, CLI or editor extension; breaking it = disqualification)
 - Stay inside the arena folder. Never read, list, search or index anything outside it
   (the rest of the disk is private). Do not upload files anywhere except as context to your model.
 - Write ONLY the .py the organizer assigned to you. Never edit, move, rename or delete other files.
 - Do not run anything: no commands, scripts, installers, package managers, git, or the game itself.
 - Do not create files or folders (no caches, logs, backups, .vscode/.idea/.cursor/.claude/.kiro etc.).
   If your tool creates workspace files by itself, stop and tell the organizer.
 - Do not change system settings, environment variables, PATH, startup items or other apps.
 - The referee logs every change in the folder (file, time, size, hash); tampering is detected.

2. INTERFACE: MODEL_NAME = "AI_Competitor"; create_agent() -> object with
   decide_action(self, perception) -> 'UP'|'DOWN'|'LEFT'|'RIGHT', taken from perception["valid_actions"].

3. TIME: max 15 ms per call (time.perf_counter, GC paused). Over 15 ms = random move.
   Live grid 192x108 (3840x2160 px); headless 50x35 (1000x700).

4. CODE SIZE: every character counts. Rank = max_score * (1 - 0.05*log2(your_chars/shortest_chars)).

5. ANTI-CHEAT (AST audit, violation = disqualified)
 - Forbidden imports: sys inspect subprocess shutil socket urllib requests http ctypes multiprocessing
   threading importlib builtins gc os pathlib pickle.
 - Forbidden calls: open eval exec compile globals locals getattr setattr delattr __import__.
 - No __dunder__ attributes except __init__, __name__, __len__. No learning or data kept between games.

6. PHYSICS (block_size 20: UP=(0,-20) DOWN=(0,20) LEFT=(-20,0) RIGHT=(20,0))
 - Food: +1 score, +1 length. Death: food on every 2nd body cell; respawn length 1, score 0.
 - <100 wrap-around, nothing kills. >=100 40 s warning (~600 turns), then own body kills.
   >=200 walls kill, no wrap. >=300 enemy bodies kill; head-on kills everyone there with >=300.
 - Below 300 every body (rivals, DQN snakes, the human) can be crossed, so bodies overlap a lot.
   The turn your score reaches 300 that is over: a 300th food on or next to another body/head can
   kill you on that same move, and from then on every other snake is a wall.
 - Tick: all choose -> all move (wrap if score before move <200) -> eat (tail cell re-added;
   ties go to first snake in list) -> deaths checked with score after eating.
 - Entering a tail cell that is leaving is safe, except right after that snake ate.
 - STARVATION: 1500 turns (100 s) without eating = death at any score (stalling or circling
   forever is not allowed). perception["turns_without_food"] / ["starvation_turns"] show the clock.
 - Default snakes = tactics + 3 (min 10; spare slots = the human player + DQN snakes that learn from
   everyone's experience); default foods = 0.8 x snakes (min 8).
 - Episode ends when every snake died once; all respawn. Leaderboard = max score ever x size factor.

7. PERCEPTION (read-only dict): my_name, my_head (x,y), my_body (head..tail), my_direction, my_score,
 width, height, block_size, foods, enemies [{id, head, body, direction, score}], active_rules
 {self_collision, self_collision_warning, wall_collision, enemy_collision, toroidal_world},
 state_vector_16, previous_reward, died_last_step, valid_actions (all 4 at length 1),
 turns_without_food, starvation_turns.

8. WHAT TO REVIEW IN telemetry.json BEFORE OPTIMIZING (your entry is llm.<your file name>)
 - ranking: your max_score vs ranking_score -> how much your code size costs you.
 - deaths + death_score_phase: "self" at <300 = you trap yourself; "enemy" at 300+ = you hit a body;
   "starvation" = you stalled (e.g. circling your own tail) instead of eating.
 - killed_by / kills: who blocks you and whom you block.
 - median_turns_to: how fast one life reaches 10/100/200/300 (lower = faster scoring).
 - last_lives: [score, cause, killer, turns lived] of your recent lives.
 - ms: keep p99 and max far below 15. errors/invalid/timeouts must stay 0.
 - Compare with the files ranked above you in tacticas\.
