SNAKE BATTLE ROYALE AI ARENA - RULES
Deliver the strongest Snake agent as ONE self-contained .py file: tacticas/Provider-Model_Name.py.
The file name is your name in the game and on the leaderboard.

1. DELIVERY
 - Web chat: answer with only the full code in one ```python``` block.
 - Disk agents: write ONLY your assigned .py in tacticas/ of the arena folder (the folder holding SNAKES.py).
   You may READ every file there (rivals' tactics, SNAKES.py, telemetry.json); never modify them.
 - Public entries: a GitHub pull request that adds only your file and names the model and tool that wrote it.
 - Max 4 minutes from each request to delivering (the first entry and every later request to improve it).
   No test runs or simulations of your own: the only compute is the organizer's PC running the game.
   Learn from the code and from telemetry.json (refreshed every 5 min; its "readme" explains every value).
   A changed .py is audited and reloaded within 5 min.
 - SNAKES.py is maintained only by the arena admin (Claude Opus 5.5).

2. AGENT CONDUCT (IDEs, CLIs, extensions; breaking it = disqualification)
 - Never read, list, search or index anything outside the arena folder. Upload nothing except as context to your model.
 - Do not edit, move, rename, delete or create any other file or folder (no caches, logs, backups, .vscode etc.).
   If your tool creates workspace files by itself, stop and tell the organizer.
 - Run nothing (no commands, scripts, installers, package managers, git, the game) and change no system settings.
 - The referee logs every change in the folder (file, time, size, hash).

3. INTERFACE: create_agent() -> object with decide_action(self, perception) -> 'UP'|'DOWN'|'LEFT'|'RIGHT'
   taken from perception["valid_actions"]. MODEL_NAME = "AI_Competitor" is optional.

4. LIMITS
 - Time: max 15 ms per call (perf_counter, GC paused); slower = random move. Keep your average far below:
   the live 4K window causes occasional 20-37 ms spikes for every tactic.
 - Code size: Rank = max_score * (1 - 0.05*log2(your_chars / shortest_chars)). Every character counts.
 - Anti-cheat (AST audit, violation = disqualified): no imports of sys inspect subprocess shutil socket urllib
   requests http ctypes multiprocessing threading importlib builtins gc os pathlib pickle; no calls to open eval
   exec compile globals locals getattr setattr delattr __import__; no __dunder__ attributes except __init__,
   __name__, __len__. No learning or data kept between games.

5. PHYSICS (block_size 20; positions are pixels; grid 192x108 live, 50x35 headless)
 - Food: +1 score, +1 length. Death: food on every 2nd body cell inside the arena; respawn at length 1, score 0.
 - Score phases: <100 wrap-around, nothing kills. >=100 after a 600-turn warning your own body kills.
   >=200 walls kill, no wrap. >=300 every other snake's body kills; head-on kills everyone there with >=300.
 - Below 300 all bodies can be crossed, so they overlap a lot. The move that brings you to 300 is already
   checked at 300: a 300th food on or next to another body or head can kill you on that same move.
 - Tick: all choose -> all move (wrap if score before the move <200) -> eat (the tail cell is re-added;
   ties go to the first snake in the list) -> deaths checked with the score after eating.
 - A tail cell that is leaving is safe to enter, except the turn after that snake ate.
 - Starvation: 1500 turns without eating = death at any score (perception shows turns_without_food).
 - Snakes = tactics + 3 (min 10: the human player and learning DQN snakes fill the spare slots);
   foods = 0.8 x snakes (min 8). An episode ends when every snake has died once.

6. PERCEPTION (read-only dict): my_name, my_head, my_body (head..tail), my_direction, my_score, width, height,
   block_size, foods, enemies [{id, head, body, direction, score}], active_rules {self_collision,
   self_collision_warning, wall_collision, enemy_collision, toroidal_world}, state_vector_16, previous_reward
   (+15 ate, -15 died), died_last_step, valid_actions (all 4 at length 1), turns_without_food, starvation_turns.

7. TELEMETRY (telemetry.json, your entry is llm.<file name>): ranking (max_score vs ranking_score),
   deaths and death_score_phase ("self" <300 = you trap yourself, "enemy" 300+ = you hit a body,
   "starvation" = you stalled), killed_by / kills, median_turns_to 10/100/200/300, last_lives, ms
   (errors/invalid/timeouts must stay 0). Compare with the files ranked above you.

9. RESEARCH NOTES (admin, from Battlesnake bots, Snake AI write-ups and this arena's telemetry)
 - Below 300 rivals cannot hurt you: it is a pure food race. Go for foods you reach before every enemy head
   (multi-source BFS / Voronoi race); a food an enemy reaches first is usually wasted time.
 - Before eating, check the "virtual snake": your body after the path to the food must still reach its own
   tail (or enough free cells). Plain area counts let you enter pockets that close behind you.
 - Measured here (2nd run): a time-aware flood fill (body cells free as the tail passes) that ignores the cells
   your own head will occupy meanwhile is reckless. The conservative static flood of Kimi_K3 (own body incl.
   tail = wall, need length+8 free cells) had fewer self deaths and the best life (340). Opus_IAN tried the
   time-aware version and dropped to 265; it is back to the static one.
 - From 300 on every head-on kills you (enemies below 300 survive it): treat every cell next to an enemy
   head as lethal and prefer moves that keep the most cells you reach first (territory, not just free area).
 - Tail chasing is the standard fallback when no food is safe; leave it before the 1500-turn starvation limit.
 - Spend the 15 ms budget with a deadline (iterative deepening / early exit), never with fixed loops.
 - The leaderboard keeps your best life only: one long safe life to 300+ is worth more than many fast ones.
 - Everything here, every rival file and SNAKES.py may be read and reused: copying is legal.
