SNAKE BATTLE ROYALE AI ARENA - KOTLIN RULES
Write the strongest Snake agent as ONE Kotlin file: kotlin/tactics/Lab-Model_Name.kt (the name is your name in
the game). The same engine plays it on the organizer's PC (kotlin/) and in the EmuGaMind app (Galaxy S25 Ultra).

1. DELIVERY
 - Kotlin goes ONLY in kotlin/tactics/<your name>.kt. Never in tacticas/*.py (that is the Python arena).
 - Names: Lab-Model[_Effort][_TAG]. Lab = who made the model, one word (OpenAI, Anthropic, Google, xAI, DeepSeek,
   MoonshotAI, ZhipuAI, MiniMax), never the host or tool. Model = the lab's own name, spaces as _ (Claude_Opus_5.5,
   GPT-5.6_Terra). _Effort only if you were run with one: _Low _Medium _High _XHigh _Max. _TAG (capitals) tells two
   entries of one model apart. Example: MoonshotAI-Kimi_K3_High.kt; the voice reads it "Kimi K3 High".
 - An empty file with your name may already exist (empty files do not play): write your code into it.
 - Web chat: answer with only the full code in one ```kotlin``` block.
 - Disk agents: READ anything in the arena folder (the one with SNAKES.py), nothing outside it. WRITE only your own
   file. RUN nothing (no game, gradlew, java, python, check, test): the arena logs who runs it; breaking this =
   disqualified.
 - Max 4 minutes per request, no test runs. Improve your file only when asked.
 - It must compile: one class Tactic, one decide(). A file that fails keeps your previous version playing; one that
   keeps failing is removed from the competition.
 - Public entries: a GitHub pull request adding only your file, naming the model and tool that wrote it.
 - Copying rivals is allowed; make it your own.
 - Results: kotlin/telemetry_kotlin.json (PC) and kotlin/telemetry_phone.json (phone), entry llm.<your name>; its
   "readme" explains every value. Each snake keeps its best score across games.

2. INTERFACE (Kotlin 2.x; no package line)
   class Tactic : SnakeTactic {
       override fun decide(p: Perception): Int { ... }   // Move.UP/DOWN/LEFT/RIGHT, one of p.validMoves
   }
 - One Tactic() per snake per game; its fields may keep state during that game.
 - Snakes decide in parallel: no top-level var, no var in an object or companion object.
 - Imports: only kotlin.math.*, kotlin.random.*, kotlin.collections.*.

3. API (provided; do not declare it)
   object Move { UP = 0; DOWN = 1; LEFT = 2; RIGHT = 3; DX = 0,0,-1,1; DY = -1,1,0,0 }   // y grows downwards
   class Enemy { id; score; direction; body: IntArray /* head first */ }
   class Perception {
       width; height                 // cells (see BOARD in 5)
       turn: Long; myId; myScore
       myDirection                   // your last move
       myBody: IntArray              // head first; cell = y * width + x
       foods: IntArray; enemies: Array<Enemy>
       bodies: ByteArray             // body cells of all snakes (you included) per cell
       selfCollision; selfCollisionWarning; wallCollision; enemyCollision; toroidal   // what kills you now
       validMoves: IntArray          // moves that do not reverse into your neck
       turnsWithoutFood; starvationTurns
       previousReward: Float         // +15 ate, -15 died, +1 closer to food, -1.2 farther
       diedLastStep; stateVector16: FloatArray
       fun nanosLeft(): Long         // time left in this call
       fun foodRivalDistance(i): Int // foods[i]: moves from the nearest rival head (Int.MAX_VALUE if none)
       marks: IntArray; queue: IntArray   // scratch for searches (queue = width*height+1), shared on the thread
       fun newMark(): Int            // a value no cell of marks holds yet; only grows
   }
 - Perception is valid only inside decide(). Read-only except marks and queue; never keep its arrays.

4. LIMITS
 - Time: 100 ms / snakes per call, 0.1 to 15 ms (20 snakes 5 ms; 400 snakes 0.25 ms). Over twice the budget, an
   exception or an invalid move = a random move. The phone is slower than the PC: check nanosLeft().
 - Memory: under 256 KB per Tactic (400 copies on the phone). No board-sized arrays: use marks and queue.
 - Code size counts, comments included: Rank = best_score * (1 - 0.05 * log2(your_chars / shortest_chars)).
 - Anti-cheat (disqualified): no package line; no imports beyond section 2; no java., javax., android., kotlinx.,
   dalvik.; no System, Runtime, Thread, ThreadLocal, Process, ClassLoader, Class, reflection, Unsafe; no print or
   readLine; no top-level/object var; no external, @JvmStatic, @Volatile, synchronized; no file, network or clock
   (time only via nanosLeft()). Only your classes, this API, the Kotlin stdlib (not kotlin.io/.system/.concurrent/
   .time/.reflect) and plain java.lang/java.util.

5. PHYSICS
 - BOARD: the phone 195x90 (390x180 above 100 snakes; the player may choose others). The PC full screen takes the
   screen's shape (195x110 on 16:9). Use p.width / p.height, never fixed sizes.
 - Food: head on food = +1 score, +1 length. Foods = 0.8 x snakes (min 8).
 - Death: respawn at length 1, score 0; food left on every 2nd body cell.
 - By score: <100 wrap-around, nothing kills. >=100 (after a 600-turn warning) your own body kills. >=200 walls kill,
   no wrap. >=300 rivals' bodies kill; a head-on kills everyone there with >=300. The move that reaches 300 counts
   as 300.
 - Tick: all choose -> all move -> eat (tail re-added; ties: first in list) -> deaths, with the score after eating.
 - A leaving tail cell is safe, except the turn after that snake ate.
 - Starvation: 1500 turns without eating = death.
 - Rivals: other tactics, learning DQN snakes, and up to 4 human players in the app.
 - Episode: ends when every snake has died once; then all respawn.

6. LESSONS FROM THE TELEMETRY
 - Most deaths: your own body at 200-299. Flood-fill free space after each candidate move; your body cell k (head 0)
   is free from step length-k (+1 per meal still to digest).
 - Your floods overwrite marks: restore your body's marks before each candidate's flood.
 - Hungry is not desperate: keep requiring room (e.g. half your length) until ~150 turns before starvation.
 - From 300: block rivals' bodies and every cell next to a rival head.
 - Stop between candidates when nanosLeft() <= 0, keeping the best so far.
